# Spoken drafts for visual questions

During an active camera/screen preview, **Speak your question → Record visual question** requests this device's microphone for up to ten seconds. **Stop and transcribe question** ends recording and submits only the audio to the paired Nexus laptop's existing local transcription worker. Reaching ten seconds also stops and requests transcription once. No image is submitted and no model answer is requested by recording or transcription.

A successful transcript is a review draft. **Use transcript as question** explicitly copies it into the visual question field, where it can be edited. The owner must then separately choose **Ask about this frame locally**, which samples a new frame at that later moment. **Discard question transcript** preserves the existing typed question. This is not simultaneous audio/video analysis, hands-free visual conversation, background listening or automatic image sharing.

## Local processing and lifecycle

The microphone request asks for audio with echo cancellation/noise suppression and `video: false`. The application accepts only live audio tracks with no video, bounds accumulated recording to 512 KiB, and rejects empty recordings. Encoded audio uses the browser's MediaRecorder format and is sent only through the existing controller-authorized local voice proxy. No browser/cloud speech-recognition API, hosted model or voice-provider request is used. On a phone, audio leaves that phone for the paired Nexus server and its local transcription worker.

Pending microphone permission expires after fifteen seconds. JavaScript cannot dismiss the browser prompt; cancellation/expiry invalidates acceptance and blocks another request until the pending promise settles. Late streams are stopped, including after navigation/unmount. Owned tracks/recorder/timers are released on stop, error, explicit cancellation, capture view teardown, disabled state, hidden/pagehide or another Nexus conversation's cooperative ownership notification. The existing conversation channel is used to announce this explicit recording and answer active-session probes; this is cooperative application coordination, not a system-wide microphone lock. Existing unrelated manual/native audio capture is outside that lock claim.

Transcription stops waiting after thirty seconds. Aborting the client request does not establish that the existing local proxy/worker stopped processing previously received audio. Completion can remain uncertain; there is no automatic retry. Capture's own sixty-second preview limit can also tear down a pending recording/transcription. Nothing resumes automatically, and existing microphone/background preferences are not changed.

The typed visual question and image controls are disabled during recording/transcription. Empty, non-string, control-character or over-1000-character transcripts are rejected without truncating the question's meaning or overwriting existing text. Using a transcript clears the previous visual answer; failed/cancelled/late work does not replace the typed question. Draft audio/transcripts are not added to owner memory, knowledge, visual history or diagnostic receipts. Nexus adds no persistent recording or transcript file; browser/request/worker memory necessarily holds transient data during processing.

## Evidence and remaining work

Tests use a fake MediaRecorder and owned synthetic audio tracks/bytes with intercepted local transcription responses, not a personal microphone or actual Whisper inference. They verify explicit capture, video-free request intent, track release before upload, preserved typed input, draft review/copy/discard, no automatic image submission, cancellation/late permission, stop-time late transcript discard, ten-second limit, denied permission, hidden-page/conversation handoff, empty/oversized audio, recorder-stop failure and oversized-response rejection. Populated desktop/phone review layouts are inspected, alongside capture, typed visual questions and normal/background conversation regressions.

Actual microphone/codec/Whisper accuracy and native Windows/Android acceptance remain unverified by fixtures. A suitable local vision/completion model is still required for the later image question. General voice-directed capture, continuous vision, automatic spoken visual answers and durable reviewed visual evidence remain separate architecture work.
