# Reviewed assistant draft files

Review answer as draft opens the current answer in an editable title/text preview. Cancel makes no save request. An open edited preview survives later assistant replies; changing workspace or losing controller access clears it rather than silently moving it into another workspace. Unconfirmed preview text is page-session state; reloading discards it. Confirm and save draft file explicitly writes the reviewed text as a new UTF-8 Markdown artifact in `.gulf-wing/assistant-drafts` on the host. The owner chooses the workspace label. The title is metadata, not a filesystem path; the generated filename contains only an opaque reference and `.md`. No selected source folder, existing document, application or external account is modified. No model or provider is contacted by saving. Saving a draft does not complete the task described by its content or establish that generated claims are true.

Saved drafts lists up to twenty recent records in the chosen workspace. Download checks the saved content hash and returns an attachment, not inline HTML. The Android client downloads from its paired host; the managed original remains on that host. Controllers are trusted owner devices, not isolated customer identities. Both reads and writes require controller authentication; writes also require same-origin validation and an explicit confirmation field.

The API accepts only request ID, title, scope, text and confirmation. Drafts require nonempty text, at most 40,000 UTF-8 bytes, a title up to 80 characters and a valid workspace. Caller paths, filename extensions and overwrite flags are rejected. A store supports up to 500 recorded drafts; deletion/retention controls remain separate work. Metadata is stored in Foundation SQLite. Existing schema-7 stores receive a pre-migration backup before schema 8 adds the draft table. Existing tasks, memory and operation records are preserved.

Files are created exclusively without overwrite and read back before a receipt is committed. Repeating the same request reference and exact reviewed content reuses the verified artifact; changed content/title/scope under that reference is rejected. Editing the preview creates a new request reference. If a crash leaves a file without a committed row, an explicit retry can reconcile only an exact matching read-back. A partial, changed, missing or redirected artifact is never silently overwritten or repaired. A partially written unrecorded file may require later manual cleanup; this is not a claim of atomic transactions across SQLite and the filesystem.

The managed directory is checked for redirection and file reads reject links/nonregular/oversized artifacts before hash comparison. These checks are not OS isolation from arbitrary same-user code. Markdown is literal saved text; Nexus does not execute it. Files and metadata are local plaintext under existing device access controls. Restoring draft history requires both SQLite metadata and the corresponding artifact directory; a SQLite-only backup is not a complete draft-file backup.

This is the first reviewed create-only artifact action in architecture milestone 4, not permission for arbitrary file mutation, browser automation, general process execution or third-party actions. Cloud tests use synthetic records and temporary directories. Windows directory/ACL behavior and owner download acceptance require native verification.
