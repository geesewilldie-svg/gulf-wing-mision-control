# Conversational saved REA result review

In Auto/Local mode, type or say **Show saved REA tests** or **Show saved REA test history**. Nexus reads the existing fixed private metadata receipt store and displays the saved history inside the assistant, reusing its explicit refresh and JSON export controls. The initial response performs no duplicate automatic read. It does not run REA, open/attach a browser, invoke MCP, inspect a site, install a package or contact a provider.

The controller/same-origin boundary applies before receipt access, and Knowledge-only, Compare and hosted modes reject locally. Per-question external-sharing/public-query flags do not turn this command into inference or public research. Malformed command continuations show help rather than combining review with execution. Negations and unrelated website-inspection requests are not silently converted into tests.

The same existing bounded history service inspects up to 100 fixed receipt slots, showing the newest twenty valid projected records and reporting shown/valid/withheld/occupied counts. Missing, unsafe/unavailable and available stores remain distinct. Unreadable, malformed, duplicate or unsafe records remain preserved; raw page/tool output and arbitrary private paths are excluded by projection. Recorded verified, cancelled and failed-or-unconfirmed outcomes describe those runs only. Historical success does not establish current package/runtime readiness, general site inspection or signed-in browser control. `generalSiteInspectionReady` remains false.

The short spoken reply gives state/counts and limitations instead of enumerating evidence IDs or private record metadata. Lookup resets recent conversation history and clears old memory/task mutator references. Returned runs do not become execution, retry or permission targets. An absent store is not an instruction to create one automatically; a new owned-browser self-test still requires its existing separate explicit control in Connections.

The browser download contains only the visible projected history and remains an owner-managed copy. Refresh/export do not rerun tools; denied refresh clears old UI results. There is no new persistent receipt, setting, grant or adapter registration. Existing history storage and tool execution contracts remain authoritative; see [owned-browser diagnostic](nexus-rea-owned-browser-self-test.md).

Validation covers exact/help grammar, missing/corrupt/unsafe store preservation, all three historical states, raw-page/path exclusion, zero network effects, controller/origin/mode gates, compiled production receipt reads, direct UI reuse, real browser JSON downloads and denied-refresh clearing. Desktop/phone layouts follow the shared spacing contract. These disposable receipt/UI tests do not run a real REA process or establish native Windows browser readiness.
