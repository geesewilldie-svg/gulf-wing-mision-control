# Installed runtime model details

Connection activity → Installed local models now offers **Inspect model details** for an explicitly inspected simple local model name with a reported digest. This reads runtime metadata rather than running inference, downloading weights, importing an archive or changing the saved/request model selection.

The controller-only, same-origin agent endpoint accepts exactly `action: local-model-details`, `model` and `digest`. It rechecks the current bounded local catalog, requests `POST http://127.0.0.1:11434/api/show` with only `{model, verbose:false}`, then rechecks catalog digest/size/modification time and configured selection. A missing/replaced model or changed selection rejects acceptance. This first slice excludes provider namespaces, URLs and cloud-selector names. A response declaring a remote model is rejected. No caller runtime options, prompts, source excerpts, credentials or destination are accepted.

Two concurrent inspections per server process, a 12-second outer deadline, existing 5-second catalog checks and 500 KB response bounds limit the operation. Cancellation propagates without retry. The projected response includes only reported format, family, architecture, parameter size/count, quantization, declared context/embedding length and up to twenty deduplicated capability identifiers with coverage. Missing/invalid values remain unknown. Raw model templates, Modelfiles/paths, system prompts, messages, license bodies and arbitrary metadata are omitted from the browser result and are not persisted by this operation.

Declared context is not the actual configured request context. Reported capabilities do not grant Nexus tools or establish adapter support. A catalog digest and runtime metadata are reported identities rather than independently authenticated bytes. Hardware fit, loaded state, generation success and model readiness still need distinct evidence. Existing typed one-answer model selection and private-context routing remain unchanged.

Official contract reviewed November 26, 2026: [Ollama Show Model Information](https://github.com/ollama/ollama/blob/main/docs/api.md#show-model-information) and [server handler](https://github.com/ollama/ollama/blob/main/server/routes.go). The reviewed upstream source distinguishes local show from cloud routing; compatibility with every installed Ollama version is not inferred. Validation uses bounded synthetic responses and an owned loopback runtime fixture, not actual model inference or native Windows runtime acceptance.

A separate explicit [fixed local inference check](nexus-local-model-check.md) is now available after completion capability is reported. It generates only the fixed diagnostic prompt and reports a time-bound single-test outcome; inspecting details alone still performs no inference.
