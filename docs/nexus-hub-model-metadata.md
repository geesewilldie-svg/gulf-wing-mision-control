# Public Hugging Face model metadata

Connections → Models and tools → **Hugging Face model metadata** supports an explicit public `owner/model` lookup and optional full 40-character commit revision. Leaving the revision blank resolves `main`, then fetches metadata again at its immutable commit. A mismatched returned repository/commit fails rather than mixing revisions.

This is an anonymous metadata connector, separate from installed Ollama models and inference routing. Only the validated public repository ID/revision is sent to the fixed `https://huggingface.co/api/models/…/revision/…?blobs=true` endpoint. The controller-only same-origin API accepts no custom endpoint, token, question, file, private excerpt or arbitrary branch. Fetches use GET, no credentials, no redirect following, no cache, a 10-second combined deadline and a 2 MB JSON limit. At most two lookups run concurrently in one server process; no automatic retries or alternate providers are used.

The response projects known fields: repository, immutable revision, lookup time, source commit URL, reported license/access, artifact filenames, bytes, LFS SHA-256 and Git blob IDs. A Git blob ID is not labelled as an independently verified file SHA-256. Missing license/hash/size stays unknown. Invalid paths, duplicate filenames and contradictory size fields are withheld. Known bytes are a subtotal; total bytes remains unknown when sizes are missing or records are withheld. A manifest above 2,000 files is rejected; at most 50 validated records are displayed/exported, with valid, omitted, withheld and unknown-size counts.

The result and visible JSON download are metadata snapshots, not a durable installed-model registry. No weights or repository code are downloaded/executed, no remote code is enabled, no model is selected/imported, and no generation runs. License metadata is reported, not legal review; artifact digests are reported, not downloaded-byte verification. The owner's 8 GB laptop is not assumed capable of running any particular model. Acquisition still needs exact file selection, license/runtime review, destination/capacity checks, bounded verified downloads and separate import/readiness checks.

Validation uses controlled transport fixtures, API authorization checks and rendered desktop/Samsung-phone workflows. The official Hub API/docs live probes from this cloud environment were blocked by an HTTP proxy CONNECT 403 policy response; live service/schema acceptance remains unverified. The connector fails with a bounded public-metadata-unavailable response rather than claiming access or falling back. No policy change or credential installation was made. Native host network access remains observable only through an explicit owner lookup.
