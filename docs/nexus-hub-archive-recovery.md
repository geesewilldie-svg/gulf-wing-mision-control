# Reconcile a published file from an uncertain transfer

In Local model archive, **Reconcile published file** is offered for an inspected `started` or `publication-unconfirmed` receipt with an inspectable final `model.gguf`. The action reads that existing file, not `model.partial`. It cannot resume a partial download, retry a network request, import a runtime model, stop an older process or declare that an older process has ended.

The request binds the selected slot to the SHA-256 of the exact inspected original receipt. A changed receipt is rejected before hashing. The existing bounded current-file checker then validates file/receipt/directory identities, size and full hash against the local recorded expectation. Size/hash mismatch yields a comparison result without a recovery write. Cancelled/failed/completed receipt states are not eligible for this separate reconciliation action; completed records keep their existing read-only check.

A match can create one separate `recovery.json` in the existing private slot. It records a recovery ID/time, original run/state/receipt digest, observed size/hash and no-import/no-inference flags. The original receipt and model are not rewritten, renamed, deleted or promoted to a new transfer outcome. The file checker rechecks file and original receipt identity/content after recording recovery; a change prevents an accepted result. A recovery record that was already written can remain when cancellation or a later check fails.

Recovery metadata uses exclusive creation, bounded known fields, same-handle readback and directory/file checks. Repeating a matching reconciliation rehashes the file but returns the existing recovery identity/time without rewriting it. Existing malformed, unsafe or differently bound recovery metadata is retained and blocks replacement. An interrupted metadata write can leave an unavailable recovery file; automatic metadata repair/replacement is not claimed. These limits favor retaining evidence over silently overwriting it.

Archive inspection reports separate recovery status: recorded, not recorded, source changed, or unavailable. Original transfer outcomes stay visible. A recorded recovery is historical evidence of agreement with that local receipt, not a current hash result, independent source authentication, fresh license review or proof of inference readiness. If an original receipt changes later, its older recovery is not shown as current. A new explicit reconciliation rechecks bytes rather than trusting the prior recovery timestamp.

The controller-only same-origin API accepts exactly `{action:"reconcile",slot,receiptSha256}`. No caller paths, expected digests, URLs, credentials, transfer, deletion or runtime options are admitted. It shares the existing one-check-per-local-server admission and 10-minute operation deadline. Metadata publication/cleanup can outlast cancellation; completed metadata is retained and an uncertain response must be inspected before repeating.

Tests use tiny local synthetic fixtures and the compiled production API. No source/provider or real model transfer is needed. Native Windows reconciliation remains acceptance work. Automatic download resume, original-run classification, recovery-file repair/versioning, pruning and runtime import remain later milestones.
