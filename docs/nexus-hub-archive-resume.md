# Resume a retained partial into a new archive run

Local model archive offers **Resume retained partial** when an inspected non-completed source record has a regular, nonempty `model.partial`, no published final file, and a prefix size no larger than the recorded artifact. The owner reviews the license again and explicitly requests an archive-only copy. No automatic resume/retry is started by inspection, page load, restart or update.

The request accepts only the source slot/receipt hash, expected recorded license and explicit review/archive-only acknowledgments. Caller paths, source URLs, byte ranges, credentials, destinations and runtime actions are rejected. The original receipt must still match the inspected hash. Published files are handled by inspection/reconciliation instead of this resume action.

Resume re-reads the immutable public Hub metadata and checks the original artifact size/hash/license plus current archive capacity using the existing transfer admission and limits. It copies the retained prefix through a read-only handle into a newly claimed archive slot, checking source file/receipt/directory identity, size, mtime and ctime around the copy. The original receipt, partial bytes and file mtime stay unchanged. An older process is neither stopped nor assumed inactive; a changing source rejects the copy.

For a partial prefix, the server constructs `Range: bytes=<prefix>-` and requires HTTP 206 with exactly the expected start/end/total `Content-Range`. Any supplied Content-Length must equal the remaining bytes. The restricted HTTPS redirect policy preserves the range and sends no account credential. An ignored/incorrect range fails without appending a full response, falling back to a full download or automatically retrying. If all expected bytes were already retained, only source metadata is fetched; the complete local prefix is copied and verified without a model-body request.

The new file still requires full size/SHA-256 verification and local hash readback before create-only publication. Its receipt records the original slot/run/receipt hash and prefix byte count as resume provenance. Original outcomes remain unchanged, including failed or cancelled runs whose owned partial could not previously be cleaned up. A new failed/cancelled attempt records its own outcome and cleans only its identifiable new partial; it never deletes the original retained source. For incomplete runs, resume provenance describes the requested source, not successful verification.

The current process-wide transfer gate is shared between fresh and resumed transfers, including separately bundled route entries. Existing 4 GiB, 10-minute operation, 100-slot and conservative capacity policies apply; both the original partial and new file consume disk. Multiple server processes against one archive are not supported. Cancellation or publication uncertainty must be inspected before another explicit attempt. Complete copies may exist if cancellation arrives after publication.

Successful resume does not execute, import, select or activate the model. Deletion/pruning, automatic resume, source-run liveness classification, broader runtime import and cross-process coordination remain future work. Tests use tiny synthetic local files with mocked metadata/delivery responses; live Hub/CDN range acceptance and native Windows resume behavior remain unverified.
