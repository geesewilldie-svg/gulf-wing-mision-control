# Conversational local model review

In Auto or Local mode, type or say **Show local models**, **List my local models** or **Show installed local models**. Nexus reads the existing bounded Ollama catalog and displays it in the assistant using the same installed-model detail controls as Connections. The initial result performs no duplicate catalog lookup. Model detail inspection and its separate fixed diagnostic remain explicit controls with their existing identity and resource gates.

The command uses the controller/same-origin Nexus endpoint and fixed loopback metadata GET, before model/provider/public-research routing. No question, owner memory, recent history or file excerpt is sent to Ollama by this catalog operation. There is no model generation, download, model selection or configuration write. Knowledge-only, Compare and hosted-provider modes reject instead of falling through. Malformed exact command prefixes show local help; negations, quoted mentions and unrelated phrases are not interpreted as commands.

The existing catalog service projects at most 100 unique valid entries from at most 1000 reported entries, with reported name, digest, size and modification time, checked time, configured-selection membership, omitted count and invalid-entry coverage. Runtime-reported metadata does not establish loaded state, hardware fit, capabilities, correct weights or inference readiness. No model from a video/catalog is presumed installed or appropriate for the owner's laptop. Runtime errors remain sanitized, do not trigger a provider fallback and leave selection unchanged.

The short response speaks counts, omissions and limitations rather than all private/project-specific model names. Structured model names remain visible to the paired owner. The response resets recent conversation history and clears prior memory/task mutator references; catalog entries do not become an edit, execution or model-switch target. Subsequent answers keep their normal scope and sharing rules.

Validation uses owned metadata fixtures, real compiled API requests and desktop/phone UI flows. It checks explicit grammar, local-only effects, controller/origin/mode boundaries, sharing flags without generation, sanitized runtime failure, reused initial results without another lookup, historical metadata labels and wrapping/spacing. This does not establish real Ollama availability, native voice recognition or actual inference on the owner's laptop.


## Inspect an exact named model

After listing, type or say **Inspect local model qwen2.5:1.5b**, substituting the exact simple name displayed by your catalog. The example is not an assertion that this model is installed. Names are case-sensitive and tags are not inferred: `fixture` does not silently select `fixture:latest`. Only the existing simple local-name profile is accepted; URLs, namespaces, cloud selectors, extra instructions and missing names show local help without a runtime request. The parser preserves trailing periods that can be part of a model ID; speech punctuation/recognition errors therefore require correcting the name rather than guessed matching.

The server first reads the current bounded catalog, requiring that exact name and reported digest within its first 100 displayed entries. It then uses the existing before/show/after identity-fenced detail service. This makes three fixed local catalog reads and one fixed local metadata POST for a successful inspection; no generation endpoint, default-model write, hosted provider or download is called. Missing/unknown/unreported-digest entries and identity/selection changes reject, retaining no detail result. The existing shared detail admission and response/time limits apply.

The assistant renders the returned detail directly without another automatic request. Refresh inspection and fixed inference testing remain explicit buttons with their established currentness/admission checks. Capabilities/context length stay runtime-reported metadata, and no capability grants an execution tool. The short spoken reply excludes the model name and raw metadata, resets recent history and clears prior mutator references. General voice-driven model switching and automatic diagnostic execution remain separate architecture work.


## Review saved diagnostics through conversation

Say **Show saved local model checks** or **Show saved model diagnostics** in Auto/Local mode. This reads the existing fixed private receipt store and displays the saved diagnostic history directly in the assistant. It does not inspect current catalog/model details, load a model, call Ollama, rerun a test, refresh a provider or change settings. Opening the returned history performs no duplicate automatic read. Explicit refresh and JSON export remain available in the reused history controls.

The response distinguishes a missing store, an unavailable/unsafe store and available history. Available results report shown/valid/withheld counts rather than treating unreadable records as absent. The existing newest-twenty display and fixed hundred-slot storage bounds, safe-file checks and known-field projection remain unchanged. Raw response text, thinking and runtime notices are not part of stored result projection. Malformed/unsafe receipts remain preserved. Historical passed/unexpected results describe completed fixed checks; they are not a complete attempt log, current readiness, loaded state or hardware evidence.

The count-only spoken response excludes model IDs and raw private details. The response clears old memory/task mutator references and recent history; saved diagnostics do not become execution or model-switch targets. Controller/same-origin/local-mode gates apply even if external sharing/public-query flags are supplied. Unsupported modes reject before receipt access. Malformed command continuations produce local help without a runtime request.

Desktop/phone tests exercise missing/corrupt history preservation, projected saved results, zero runtime/provider calls, production receipt reads, direct initial-result reuse, explicit downloads and denied-refresh clearing. Native ASR and actual local-model acceptance remain separate. See [saved diagnostic storage](nexus-local-model-check-history.md).


## Explicit fixed diagnostic through conversation

In Auto/Local mode, type or say **Run local model check qwen2.5:1.5b**, substituting an exact simple model name from your current catalog. This command is an explicit request to load that model for the existing fixed diagnostic, which can use laptop RAM/CPU/GPU. It does not mean “inspect metadata,” switch the saved default, download weights or run an arbitrary prompt. The example does not establish installation or hardware suitability. Model names/tags are not guessed; unsupported URLs, cloud/namespaced selectors, missing names and appended instructions receive local help without inference.

A fresh bounded catalog lookup resolves the requested name and digest, followed by the existing identity-fenced diagnostic adapter. Completion capability, catalog/digest/default-selection fences, shared local-inference admission, fixed eight-token/512-context request, immediate-unload request and forty-five-second diagnostic waiting deadline remain unchanged. The preliminary catalog lookup has its existing separate five-second bound. Only the application's fixed diagnostic prompt is sent to loopback Ollama; user question text, owner memory, files, recent history, image data and public-query flags are excluded. There is no hosted fallback, default change or automatic retry.

The returned projected result appears directly in the assistant using the existing diagnostic result/download controls. Rendering or downloading it does not run the test again. Passed and unexpected-completed outcomes remain distinct, and the reply reports saved versus pending history separately. The short spoken reply omits model IDs and raw output, resets recent history and clears old memory/task mutator references. No raw model response is added to the result or receipt. Historical completion is not a hardware benchmark, present loaded state or future readiness guarantee.

The request's existing cancellation behavior applies: runtime completion/unload can remain uncertain, and a completed diagnostic may already have saved metadata when a client disconnects. This command supplies no new exactly-once/idempotency guarantee; explicitly repeating it can start another test. Failed/cancelled/incomplete responses do not produce a successful result, and no rerun is performed solely to repair a pending metadata save. Use **Show saved local model checks** to review retained completed outcomes.

Validation covers exact explicit grammar, fixed generation body, missing model/completion/cancellation before generation, one generation per accepted request, saved versus unsafe-store/pending outcomes, unexpected raw-text exclusion, controller/origin/mode gates and external-sharing flags without context leakage. A compiled production request exercises an owned loopback runtime fixture and retained receipt; desktop/phone UI tests verify returned-result reuse, explicit export and spacing. These tests do not establish actual model inference or native ASR/hardware acceptance.
