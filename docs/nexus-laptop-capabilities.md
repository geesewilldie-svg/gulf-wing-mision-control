# Laptop capability registry

In Auto or Local mode, ask “Show laptop capabilities” or “What can you do on my laptop?” Nexus returns a deterministic configuration summary and readable cards without asking a model, contacting providers or dispatching maintenance. The summary names included and missing capability families so it remains useful when spoken. The lookup uses existing controller and same-origin checks; cloud, Compare and Knowledge-only modes reject the command before provider use.

The first version covers selected-file reading/index refresh, reviewed create-only managed drafts/copies, and two named Windows maintenance actions. A separate reviewed HTTPS-link opening capability is included behind local enablement and explicit confirmation. Page reading/clicking, tab management and general computer/source-file mutation remain explicitly unbuilt. This is not a full inventory of voice, memory, tasks, accounts or coding workers, and is separate from the Connected Work activity display.

Definitions have stable IDs, version, description, effects, authorization prerequisites and verification notes. The declarations describe existing adapters; they do not authorize invocation, create grants, install providers or implement a general broker. Existing path, confirmation, platform, local-enable and revision checks remain authoritative.

The read-only lookup checks local folder-selection configuration and maintenance enablement. Selected folders are not proof of current readable coverage; searches still validate sources. Missing configuration reports setup needed, unreadable configuration reports unavailable, and maintenance reports Windows required on another host. Managed drafts are labelled included in this build, not proven writable. No folder paths, account keys or private record contents are included in the report.

The same static capability facts are supplied to local answer prompts and planning prompts. No dynamic private configuration or owner memory is newly shared with external providers. This helps ground descriptions but does not guarantee a small local model follows them or verifies its own actions. Neither answering models nor planning workers gain execution tools.

This is an initial architecture registry slice for the bounded laptop adapters. General schemas/plugin activation, Windows helper/desktop takeover, arbitrary-effect reconciliation and further services remain unfinished. No database migration or new permission is required.

The selected-files description now includes a bounded original-file read: open current indexed PDFs/text through the browser or download supported indexed originals. Actual rendering depends on browser/OS support; this does not implement drive discovery, unindexed/image browsing, native app control or arbitrary execution. Existing controller, selection, size and hash checks govern each original request.

Selected files also expose a metadata-only directory navigator over the same locally chosen roots. It lists/paginates folders and file names without indexing bodies, and hands available cached previews to the existing version-checked reader. This is not drive discovery, unindexed content access or a general filesystem grant. No model or extra source permission is required merely to list metadata in those selected roots.
