# Browse-only storage locations

`Setup-Nexus-Storage.cmd` runs on the Windows laptop. Choose Add, select one of the discovered common folders or drives, review the exact local path and confirm Y to permit browsing. The command checks that the location is an ordinary available directory, resolves its canonical path and records its filesystem identity. It never edits `local-folders.json`, refreshes an index or scans descendants. Use Remove in the same command to revoke one browse grant. Source files and separate knowledge selections remain unchanged.

These choices live in `.gulf-wing/storage-browse.json`, a separate versioned local configuration with a maximum of twelve grants. Updates use exclusive local locking and an atomic temporary-file rename; malformed configuration is preserved rather than overwritten. A leftover lock from an interrupted setup is not automatically removed. The local command is the only grant-management interface; no browser operation accepts new paths or enables grants.

A drive selection is broad: paired controllers, including a phone, can list permitted descendants and read supported originals through the existing resource endpoint. Existing hidden/protected-name rules, link/junction rejection, depth/path/entry/page limits and 8 MB original-file bound still apply. Granting browse access does not grant indexing, model sharing, write access, native application execution or phone-local storage access. The current UI remains **Memory → Explore selected folders**, with browse-only drive/folder labels alongside existing knowledge selections. The **Storage galaxy** view now renders those locations and directory pages as drive/folder objects and file stars in the original spiral. See `nexus-storage-galaxy.md`.

The resource service combines current knowledge roots with the separate browse grants. It binds signed directory/file references to this combined selection and checks the granted root's physical identity before browsing or reading. Removed grants invalidate old references. Replaced roots become unavailable until selected again locally. Any source-selection change requires reloading the folder list. Already delivered bytes or completed downloads cannot be recalled. Overlapping independent grants remain independent: removing a browse grant does not remove an existing knowledge selection or another parent-drive grant.

Only knowledge roots are passed to the indexer and cached-index lookup. Tests verify a browse-only file opens while refreshing an empty knowledge selection indexes zero files, and existing indexed previews remain available when unrelated browse grants are present. Missing grants mean no additional access; corrupt browse settings stop resource browsing with an explicit error. Absolute root paths are printed locally for review but are not returned by the browser roots API.

Validation uses disposable directories and pairing configuration: local add/remove/corruption/lock/link tests, API access and identity checks, overlap/index separation, and actual text opening via the rendered desktop/mobile controls. The Windows discovery query was observed working on the owner's laptop; the new interactive grant command still needs its first native execution. No owner source or permission was changed by automated tests.
