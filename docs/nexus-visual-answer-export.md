# Explicit local visual-answer export

Connections → Camera and screen now offers **Download visual answer JSON** only while a completed local frame answer is displayed. The owner explicitly starts the browser download; opening a preview, recording/transcribing a question and asking about a frame do not download anything automatically. No additional server, runtime or provider request occurs when exporting.

The version-one JSON contains an export timestamp, unverified-model-description provenance and a fixed projection of the displayed run: requested/reported model, reported digest, client-reported source/capture time, server completion time, declared dimensions/bytes, elapsed time, current question, answer text and reported output-token count. Unknown response fields, image bytes, raw thinking, runtime context and server-supplied notice text are excluded. The application supplies the historical/unverified interpretation notice. These values are recorded observations, not independently authenticated evidence of camera content, model weights, correctness or execution.

The fixed filename is `nexus-local-frame-answer.json`. The browser controls its destination. This copy may contain private question/answer text and remains on disk after preview stops or the displayed answer is cleared. Nexus does not write an export receipt, retain an image, automatically save this answer in owner memory, or register/index the download. A later explicit file import or indexing of a selected download folder is a separate operation. This JSON is not a restore/import format and does not recreate a frame or grant execution authority.

A new request, model/question change, stale/denied response, capture stop, visibility loss or navigation retains the existing result-clear behavior and removes the export control. A completed download cannot be revoked by clearing the UI. Temporary blob URLs are revoked after the download is initiated; browser download completion is not reported as independently verified. A browser preparation failure leaves the displayed answer available with a local error message. There is no automatic retry or cloud fallback.

Validation covers explicit desktop/phone browser downloads, fixed filename/schema/provenance, preservation of question/answer and identity fields, exclusion of injected image/thinking/unknown fields, disappearance after stale results, touch target size and populated result spacing. Existing capture, cancellation, visual-question and recording cleanup regressions remain applicable. Owned synthetic image/runtime fixtures do not establish actual model decoding, native microphone/camera/chooser behavior or laptop hardware acceptance.
