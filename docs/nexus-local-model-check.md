# Explicit local inference diagnostic

Connection activity → Installed local models → Inspect model details offers **Run local model check** for a model reporting completion capability. Viewing the catalog/details never starts the check. The button explicitly requests one fixed local generation and explains that loading a model can consume laptop RAM/CPU/GPU.

The controller-only, same-origin agent endpoint accepts exactly `action: local-model-check`, the inspected simple local model name/digest, and `runTest: true`. Caller prompts, context, options, URLs, cloud selectors and provider credentials are not accepted. The diagnostic shares the existing single process-local inference slot with answers/planning, so competing local generations are rejected rather than queued or silently routed elsewhere.

The check reuses digest-bound runtime detail inspection, requires reported completion support, then calls only `http://127.0.0.1:11434/api/generate` with a fixed diagnostic system/prompt. It requests the exact marker `NEXUS_OK`, non-streaming output, thinking disabled, 8 output tokens, a 512-token context, temperature zero and immediate unload (`keep_alive: 0`). These are runtime request settings, not independent enforcement of an untrusted runtime's resource usage. No owner memory, files, current question, conversation history or caller text is supplied. No download, import or selection/provider grant changes are made.

A 45-second overall wait bound includes metadata and generation; the response is limited to 32 KB. A completed response must report the selected model (with optional default `:latest` normalization). After generation, the catalog digest and configured selection are checked again. Exact marker agreement and a non-excessive reported token count yield **Fixed local test passed**. Other completed text or excessive reported tokens yield an unexpected-response outcome, not success. Missing output statistics stay unknown. Incomplete, mismatched, changed, oversized or failed responses yield no accepted success. Raw generated text, thinking and returned context are omitted and are not saved by this diagnostic.

The result is a page-session observation of this one test: run ID, selected/reported model, inspected digest, timestamp, total elapsed time including metadata, and reported output token count. It does not establish independent model identity, sustained performance, larger-context hardware fit or future readiness. Unload is requested, not independently observed. Cancelling, closing/refreshing the panel or exceeding the wait limit can leave upstream work/load state uncertain. There is no automatic retry, cleanup generation or cloud fallback. An operator can inspect before explicitly choosing another attempt.

Contract reference: [official Ollama generate API](https://github.com/ollama/ollama/blob/main/docs/api.md#generate-a-completion), reviewed November 26, 2026. Test evidence uses synthetic responses and an owned loopback runtime fixture; no actual model generation on the owner's Windows laptop is inferred.

Completed tests now support [bounded local history and exports](nexus-local-model-check-history.md). Save failure is reported separately from test completion and never triggers another generation. Historical records are not current readiness proof; failed/cancelled/uncertain requests are not included in this completed-result history.
