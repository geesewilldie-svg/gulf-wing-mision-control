Holding, Aviation, Security Operations and Future Ventures retain their distinct manual operating desks; no live flight/security dispatch or regulatory clearance is implied. ## Release order and evidence required

### 1. Stabilize the installed laptop experience

- Verify the console-free voice startup fix on the ASUS. Latest operator evidence before that acceptance: port 8766 did not respond; the appended voice log contained Windows console-close errors. The published fix and synthetic tests do not prove the laptop is repaired.
- Confirm speech and transcription health after launcher startup and after closing the terminal. Test a spoken question, a spoken reply, next-turn listening and immediate Mute.
- Confirm Windows sign-in opens Nexus only after the updated shortcut option is installed. Validate the saved automatic-listening choice, browser permission fallback and duplicate-window behavior on the actual browser. Listening still requires an open browser, an awake laptop and valid Controller access; it is not a native always-listening service.
- Exercise service failure/recovery and session expiry, with clear visible state. Do not advertise uninterrupted/24-hour availability based on the current browser implementation.
- Validate laptop/phone/Chromebook/ScreenPad/TV operation separately. Distinguish browser emulation from real device evidence.

Exit evidence: repeatable native startup/voice/mute/sign-in checks and an understandable recovery path. No new paid provider is needed to establish this baseline.

### 2. Prove one complete useful business workflow

Run a synthetic Co-hosting lead through scoped estimate, manually recorded acceptance, one linked job, checklist completion, source-backed Nexus query and private backup/restore. Then validate an owner-approved real workflow privately. Do not turn planning forecasts into an approved price list or represent manual statuses as sent messages, collected payments or executed contracts.

Exit evidence: the record persists across devices/restart, stale edits are handled, a restored backup recovers the expected records, and the operator can explain what is real versus DEMO. Avoid expanding features faster than the core workflow can be used.

### 3. Clear voice and dependency rights before product distribution

Keep voice providers replaceable. See [Fish Audio review](fish-audio-evaluation.md). The operator's preferred reference is the Fish Audio library voice named Jarvis, ID `ce902336fafb4f89b6fd22f79739851b`, shown with Drama 3 at 1.3x in a supplied screenshot. Its publisher/voice permissions and current hosted API prices/terms remain unverified; the web app audition is not product clearance. No sample audio or model weights are bundled here.

Maintain an inventory of application dependencies, runtime code, model weights, voice packs, fonts, icons and reference assets with license/version, notices, permitted commercial use and any redistribution limits. This includes existing Kokoro/Piper components as well as any new provider. Choose the product's customer license/terms intentionally; do not automatically open-source proprietary Nexus code or claim unrestricted redistribution of third-party models.

Exit evidence: an identified permitted voice, appropriate provider/product terms, required notices, verified unit pricing and a measured cost cap. Nothing is enabled or purchased simply to complete this document.

### 4. Make external-customer access a separate security release

The current shared Controller pairing is for trusted devices, not named customer accounts or tenant isolation. Before serving unrelated customers, implement and test company membership/roles, tenant-separated data and credentials, HTTPS, recovery/revocation, retention/deletion/export, appropriate audit history and least-privilege provider authorization. Keep customer content out of unrelated tenants' search, prompts, logs and backups. Downloads alone do not establish authorization to Cursor, Manus, OpenClaw, GrockBot or Copilot.

Exit evidence: cross-tenant denial tests, account recovery/deletion tests, private backup recovery, consent/retention documentation and an authorized deployment plan. Do not expose the laptop's port through router forwarding as a substitute.

### 5. Package, support and measure a small pilot

Provide reviewed installation, upgrade/rollback, uninstall, diagnostics and support instructions. Test the supported Windows versions and realistic hardware, including browser microphone restrictions. Validate update/restart behavior when services are already running, not just a clean install. Distinguish local desktop licensing from a hosted subscription service; a desktop UI does not create SaaS identity, billing or operations automatically.

Measure time to complete the core workflow, successful sourced answers, support incidents, startup failures, end-to-end voice delay and per-customer provider costs if paid providers are later approved. Break voice delay into transcription, model response and speech startup: the current answering/audio paths can buffer complete responses, so a faster TTS engine alone is not proof of a fast conversation. Use measured results to choose any streaming work. Report real measurements, never synthetic benchmarks as customer performance.

Exit evidence: a small authorized pilot can operate and recover without developer intervention, with clear scope, support and customer terms. Decide pricing from measured costs and actual customer feedback, not an invented revenue promise or launch date.
